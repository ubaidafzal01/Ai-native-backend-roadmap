03

Semester 3 · Programming foundation

Master Java and developer fundamentals

Your university DSA and COAL courses remain the academic priority. The side-study goal is to transition confidently from C++ into professional Java development.

Side courses, in order

  1. Git and GitHub — branches, merges, pull requests, rebasing basics.
  2. Java fundamentals — Java syntax, OOP, interfaces, abstract classes, collections, generics, exceptions.
  3. SOLID principles and clean code.
  4. Linux terminal fundamentals.
  5. JUnit basics and debugging.
AI engineering track

Learn context engineering, structured prompts, AI code review, and responsible use of Claude Code or GitHub Copilot. Practice giving an agent a small, well-specified task and checking its output.

Final project

Build Your Own Redis in Java

A TCP server that speaks the Redis protocol (RESP): SET/GET with expiry, lists, pub/sub and optimistic locking, backed by your own data structures, with unit tests and a clean GitHub repository.

Build Your Own Redis in JavaReinventing D Wheel · YouTube
Why this semester

Your first real Java project: it turns this semester's Java, OOP and collections into a working server, and puts your DSA course (hash maps, lists) to direct use.

Completion test

You can independently build, test, debug, and explain a Java program, and redis-cli can talk to your server.

Write a Database from Scratch

A storage engine with fixed-size pages, a page buffer, B+tree indexes (including non-unique keys), and queries with filtering, sorting, offset and limit. Build it in Java to keep strengthening your main language.

06

Semester 6 · Distributed fintech systems

Distributed systems and fintech engineering

Side courses, in order

  1. Microservices architecture and service communication.
  2. Apache Kafka or RabbitMQ.
  3. Distributed systems fundamentals — consistency, fault tolerance, timeouts, retries.
  4. Database isolation, concurrency, and transactions.
  5. Idempotency, transactional outbox, event-driven architecture.
  6. Payment systems basics — transaction lifecycle, ledgers, reconciliation.
AI engineering track

Begin Python, LLM APIs, structured outputs, tool calling, and AI application security. Learn how to expose authorized backend information to AI tools safely.

Final project

Distributed Payments & Wallet Platform

Your own event-driven payments core: users hold wallets, send money to each other and pay merchants, and every transfer flows through Kafka as a chain of events across independent microservices. Built in Java and Spring Boot and designed entirely by you, with no tutorial.

What you will build

  • MicroservicesAccount, Wallet, Payment, Ledger and Notification services behind an API gateway, each owning its own PostgreSQL database
  • KafkaApache Kafka as the event backbone, with topics partitioned by account ID so events for one wallet stay in order, and consumer groups for scaling
  • Event-driven transactionsTransfers as event-driven transactions: a choreographed saga (debit → credit → confirm) with compensating events that roll back when a step fails
  • Idempotency + outboxA transactional outbox on every service and idempotent consumers, so each event changes state exactly once even when Kafka redelivers it
  • Fault toleranceTimeouts, retries with exponential backoff, a dead-letter topic and a small tool to replay failed events
  • Isolation + concurrencyConcurrent transfers on the same wallet kept correct with row locks or optimistic versioning, proven by a concurrency test
  • Payments + ledgersA double-entry ledger, a payment lifecycle state machine, signed webhooks from a fake payment gateway and a nightly reconciliation job
  • KubernetesAll services, PostgreSQL and Kafka running on a local Kubernetes cluster (kind or minikube) with health probes and config in ConfigMaps and Secrets
Why this semester

Every side course of this semester becomes a requirement: microservices, Kafka, distributed-systems fundamentals, isolation, idempotency with the outbox, and payment ledgers.

Completion test

Demonstrate why retries don't result in duplicate transfers and how the ledger remains consistent, even when a service or Kafka broker crashes mid-transfer.

Career milestone

Aim to obtain a backend internship by this stage. Apply more widely than Tamara so you gain real team experience.

Semester 7 · Reliability and intelligence

Advanced system design and AI engineering

Side courses, in order

  1. High-level system design — load balancing, caching, sharding, scaling.
  2. Advanced distributed systems and reliability.
  3. Kubernetes fundamentals.
  4. Observability — OpenTelemetry, distributed tracing, metrics.
  5. Load testing, performance profiling, and incident response.
  6. Go fundamentals, only after your Java skills are strong.
AI engineering track

Study RAG, embeddings, vector search, AI agent orchestration, MCP, tool permissions, evaluation datasets, tracing, and human approval workflows.

Final project

Flash-Sale Ticketing Platform

A ticket-booking system built for the hardest moment in system design: a concert goes on sale and 50,000 people try to grab 5,000 seats in the same minute. You design it from a blank page, run it on Kubernetes and prove with load tests that it never sells the same seat twice.

What you will build

  • System designA written system design first: requirements, capacity estimates (QPS, storage), API, data model, high-level diagram and the trade-offs you chose
  • Load balancingAn ingress load balancer and API gateway with per-user rate limiting and a virtual waiting room for traffic spikes
  • Event-driven transactionsSeat reservation as an event-driven transaction over Kafka: hold → pay → confirm, or expire and release, with no overselling under heavy contention
  • Caching + CQRSCQRS: writes go through events while seat-availability read models live in Redis, kept fresh by Kafka consumers
  • Sharding + scalingBookings sharded by event ID with consistent hashing, and Kafka partitions sized so consumers scale out horizontally
  • KubernetesKubernetes with horizontal pod autoscaling, rolling deployments, pod disruption budgets and Kafka running as a StatefulSet
  • GoA high-throughput seat-hold expiry and queue service written in Go
  • ObservabilityOpenTelemetry traces that follow a booking across services and Kafka hops, plus metrics, SLOs and dashboards
  • Load testing + profilingk6 load tests that replay a flash sale, profiling of the slowest service and the fixes you made
  • Reliability + incidentsChaos drills (kill a Kafka broker, a pod, a shard), each followed by a written postmortem
Why this semester

A pure system-design and microservices project: load balancing, caching, sharding, scaling, Kubernetes, observability, load testing, incident response and Go, all under real contention.

Completion test

At peak load, show zero oversold seats and explain p99 latency, Kafka consumer lag, cache hit rate and how the system recovered from a broker failure, using your own traces and dashboards.

Career milestone

Begin serious preparation for Tamara-style Java, SQL, distributed-systems, and backend interviews.

Industry readiness and job applications

Side courses, in order

  2. Low-level design — classes, interfaces, SOLID, design patterns.
  3. High-level design — wallets, payments, event-driven systems.
  4. Advanced Spring Boot and SQL interview revision.

Final capstone

Production-Grade Distributed Redis

Polish your strongest project. Recommended: turn your Semester 3 Redis into a distributed service with replication, persistence (snapshots and append-only log), Docker deployment, metrics and tracing, a load-test report, architecture diagrams and security notes. Alternative: polish your Semester 6 payments platform or Semester 7 ticketing platform to the same standard.

Why this semester

Brings the whole journey together: the Java of Semester 3, the storage ideas of Semester 4, the DevOps of Semester 5, the microservices of Semester 6 and the system design of Semester 7.

Completion test

Confidently defend every architectural decision and complete realistic technical interviews without AI help.

Career milestone

Apply for eligible Tamara junior engineering vacancies and graduate opportunities before graduation, while keeping other fintech and backend companies as parallel targets.
